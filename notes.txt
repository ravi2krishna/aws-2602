    -> VPC (Virtual Private Cloud)

        -> A Virtual Private Cloud (VPC) is a logically isolated, private network environment 
        within a public cloud. VPC gives organizations total control over networking components
        like IP addresses, subnets, route tables, and gateways—while benefiting from the 
        scalability and cost-efficiency of shared public cloud infrastructure.

        -> https://www.akamai.com/site/en/images/article/2023/akamai-public-private-cloud.png

        -> https://images.netcomlearning.com/cms/images/virtual-private-cloud.jpg

        -> NOTE: Having VPC is similar to having your own data center inside AWS. 

        -> VPC is a service that lets customers(IBM) provision a logically isolated 
        section of the AWS Cloud where you can launch AWS resources(Servers) 
        in a VIRTUAL NETWORK that you define.

        -> Most Popular Applications
        
            -> https://en.wikipedia.org/wiki/Programming_languages_used_in_most_popular_websites

        -> VPC Architecture Reference 

            -> https://media.licdn.com/dms/image/v2/D4D12AQFI8sqvP4xFFQ/article-cover_image-shrink_720_1280/article-cover_image-shrink_720_1280/0/1700537758681?e=2147483647&v=beta&t=zE97TFGw5FQJEjUksqx7SohNsqqV57-IYQ_pj7K2M2U

        -> NOTE: VPC forms the backbone for Infrastructure to build any Application on cloud 

    
    -> VPC Components

        -> Subnets
        
            -> Segments of a VPC's IP address range that group resources based on 
            security and connectivity needs (e.g., public subnets for websites, 
            private subnets for databases).

            -> A subnet or sub network is an logical subdivision of an Amazon Virtual Private Cloud (VPC)

        -> Route Tables
        
            -> Rules that dictate where network traffic is directed.

            -> A route table contains a set of rules called routes, 
            that are used to determine where network traffic is directed.

        -> Gateways
        
            -> Connection points that bridge your VPC to the external internet or 
            on-premises data centers.

            -> Internet Gateway

                -> An Internet Gateway must be attached to a VPC if the resources inside the VPC 
                need to connect to resources via the open internet.

        
        -> Network ACLs (NACL)
        
            -> Virtual firewalls that control inbound and outbound traffic at the subnet level.

        -> Security Groups  
        
            -> Virtual firewalls that control inbound and outbound traffic at the instance level.

    -> Subnetting 

        -> Subnetting is the practice of dividing a network into two or more smaller networks.

        -> When you create a VPC, you must specify a CIDR (Classless Inter Domain Routing) 
        block for the VPC.

        -> The allowed block size is between a /16 netmask (65,536 IP addresses) and 
        /28 netmask (16 IP addresses).

        -> NOTE: AWS Recommends to create VPC CIDR with /16 for future purpose 

        -> NOTE: In Every Subnet, aws has some reserved IP's 

            -> The first four IP addresses and the last IP address in each subnet CIDR block 
            are not available for you to use, and cannot be assigned to an instance.

                10.0.0.0: Network address.
                10.0.0.1: Reserved by AWS for the VPC router.
                10.0.0.2: Reserved by AWS for Amazon DNS server.
                10.0.0.3: Reserved by AWS for future use.
                10.0.0.255: Network broadcast address.

    -> EBS - Limitations 

        -> Using EBS we cannot get the data directly across Multiple Availability Zones
        -> Using EBS we cannot connect to MULTIPLE INSTANCES at same time 
        -> With EBS Volumes, you can only scale up, but NO SCALING DOWN

    -> Elastic File System (EFS File Storage)

        -> Amazon Elastic File System (EFS) provides a simple, scalable 
        fully managed elastic NFS file system for AWS EC2  

        -> A Network File System (NFS) is a distributed file system protocol that 
        allows a client computer to access and manage files over a network 
        exactly as if they were stored on its local hard drives.

            -> https://edgeone.ai/media/42b9d9ea-578c-4c96-b7f9-346f3c6cf2c0.png

        
        -> Using EFS we can directly get the data across Multiple Availability Zones
        
        -> Using EFS we can connect to multiple instances at the same time

        -> Using EFS we can dynamically, scale up and down 

        -> NOTE: With EFS you need to use NFS Port - 2049, not for instances

        -> NOTE: EFS Cannot be used as Root Volume, only additional.

        -> NOTE: To Us NFS, install NFS utilities

            -> sudo apt-get install nfs-common -y

            -> Individual identities (e.g., employees, applications) assigned to a person or program,

            -> A policy is an object in AWS that defines permissions.

        -> IAM User Groups

            -> A user group is a collection of IAM users.

            -> Collections of users. 
            Grouping users makes it easier to assign and manage 
            permission policies collectively rather than individually.

        
        -> IAM Roles 
        
            -> Temporary, permission-based credentials that can be assumed by trusted entities
